# 使用者體驗審查

## When to Use

- 需要使用 ux-audit 時

評估和改善應用程式的使用者體驗。

## 適用場景

- 介面可用性評估
- 使用者流程優化
- 操作效率分析
- 無障礙功能檢查
- 互動設計審查

## 審查維度 (含 PencilPlaybook 設計心理學與量化指標)

### 1. 設計心理學原則 (Design Psychology)

| 心理學法則 | 核心原理 | 審查重點 |
|---|---|---|
| **格式塔鄰近性 (Proximity)** | 空間靠近的元素被視為同一群組 | 相關標籤與 Input 間距 (`gap-1.5`) 必須小於不同表單區塊間距 (`gap-6`)。 |
| **格式塔相似性 (Similarity)** | 外觀相似的元素被視為具備相同功能 | 同級 CTA/Button 樣式一致；禁止混用 primary 樣式於非主行為。 |
| **費茨定律 (Fitts's Law)** | 目標越大、距離越近，操作越快 | 手機主操作置於拇指熱區；最小點擊熱區必須 ≥ `44px × 44px`。 |
| **席克定律 (Hick's Law)** | 選項越多，決策時間呈對數增加 | 每屏主決策路徑唯一，次級動作隱藏或降級為 Ghost/Outline 按鈕。 |
| **米勒定律 (Miller's Law)** | 短期記憶容量為 7±2 項 | 頂部導航 ≤ 7 個、表單超過 5 欄位需進行分步驟或卡片分組。 |

---

### 2. PencilPlaybook 精確量化工程參數 (Quantitative Guardrails)

| 檢查維度 | 嚴格標準 (PencilPlaybook Standard) | 常見錯誤 (Anti-patterns) |
|---|---|---|
| **Disabled 狀態** | 嚴格使用 `opacity: 0.40` (`opacity-40`) + `cursor-not-allowed` | 誤用 `opacity: 0.50` 或直接調淡文字顏色導致對比失真 |
| **最小觸控熱區** | `min-w-[44px] min-h-[44px]` (包含 padding 補償) | 圖示按鈕僅 `24x24px` 導致手機端難以觸控 |
| **內文行距** | `leading-relaxed` (`1.5 ~ 1.6x`)，每行 45-75 字元 | `leading-normal` 造成長文閱讀壓迫感 |
| **大標題字距** | `48px+` 大標題必須加負字距 `tracking-tight` (`-0.02em ~ -0.05em`) | 大字體未調字距顯得鬆散、缺乏視覺衝擊 |
| **小標全大寫字距** | `10-12px` 全大寫 Eyebrow 必須加正字距 `tracking-widest` (`+0.06em ~ +0.1em`) | 小全大寫文字擠在一起難以辨識 |
| **焦點環 (Focus Ring)** | `ring-2 ring-offset-2 transition-all 150ms` | 移除 `outline: none` 且未提供任何焦點態 |
| **空間基數 (Grid)** | 嚴格依循 4px/8px 比例 (`4, 8, 12, 16, 24, 32, 48, 64px`) | 出現 `17px`, `23px` 等隨意數值 |
| **色彩角色上限** | 每屏 Accent 色出現次數 ≤ 2 次 | 到處都是品牌主色，視覺失去層次 |

---

### 3. 操作效率與流程

| 檢查項目 | 說明 |
| -------- | ------------------------ |
| 點擊次數 | 核心轉換任務是否在 3 次點擊內完成？ |
| 認知負荷 | 是否有不必要的填表欄位或重複確認？ |
| 錯誤復原 | 破壞性操作（刪除、重設）是否有防呆與 Undo 機制？ |
| 快捷操作 | 桌面版是否支援鍵盤導航 (Tab/Enter/Esc)？ |

---

### 4. 回饋與狀態 (State Feedback)

| 場景 | 應有回饋 (PencilPlaybook 規範) |
| ---------- | ------------------- |
| **載入中** | 骨架屏 (Skeleton) > Spinner，保持頁面佈局穩定無 CLS |
| **操作成功** | 輕量 Toast (3秒自動消失) 或 Micro-interaction 打勾動效 |
| **操作失敗** | 行內明確錯誤訊息 + 具體排錯指引（非抽象 Error code） |
| **空狀態** | 友善插圖/SVG + 一鍵建立按鈕（引導下一步動作） |
| **長時間等待** | 確定性進度條 (Progress bar) + 預估時間 |

---

### 5. 表單與無障礙 (A11y & Form Standards)

```markdown
檢查清單：
- [ ] 所有 input 均有關聯的 `<label>`（或 `aria-label`）
- [ ] 必填標示清晰，錯誤提示於失焦 (Blur) 後即時顯示
- [ ] 支援瀏覽器原生自動完成 (`autocomplete="email"` 等)
- [ ] 色彩對比度符合 WCAG 2.1 AA (一般文字 ≥ 4.5:1, 大文字 ≥ 3:1)
- [ ] 支援 `prefers-reduced-motion` 降級
- [ ] Tab 鍵焦點順序與視覺閱讀順序一致
```

```markdown
| **量化參數** (熱區 / 40% Disabled / 字距) | 7/10 | 違規 2 項 | [簡述] |
| **操作效率** (3 擊路徑 / 認知負荷) | 8/10 | 優良 | [簡述] |
| **狀態回饋 & A11y** (Skeleton / WCAG AA) | 9/10 | 符合標準 | [簡述] |

## 2. 發現之問題清單 (🔴 P0 / 🟡 P1 / 🟢 P2)

### 🔴 高優先級 (P0 - 破壞性體驗或規範違背)

  - **具體修正代碼**：`className="min-h-[44px] opacity-40 cursor-not-allowed"`

### 🟡 中優先級 (P1 - 效率或審美瑕疵)
- **問題**：[描述] → **改善建議**：[代碼或配置]

## 3. 5 秒測試與結論
- **5 秒理解度**：[使用者能否在 5 秒內理解產品核心價值與下一步？]
- **綜合評價**：[總結行動指引]
```
